# Enforce completed-result titles for block domain

**Date:** 2026-03-11 11:42
**Files:** src/modules/blocks/domain/block-policy.ts, src/modules/blocks/domain/block.ts, tests/unit/modules/blocks/domain/block.test.ts
**Severity:** high

## Problem

The block aggregate accepted activity-style titles such as `Implement onboarding flow`
or `Fix login bug`, even though the project rules require block titles to describe
a completed result. That allowed invalid core-domain data to be created and stored.

## Root Cause

The domain validation for `Block` only enforced generic string constraints on `title`
(non-empty and max length). The lifecycle policy validated status, ownership, DoD,
and blocker invariants, but it did not include the semantic rule for result-oriented
titles. Because `Block.validate` delegated all invariants to `BlockPolicy`, the rule
was simply missing from the central policy layer.

## Solution

Extended `BlockPolicy.assertLifecycleState` to validate the block title before any
other lifecycle checks and added `assertTitleDescribesCompletedResult`. The new guard
rejects common activity prefixes in English and Russian and raises a domain validation
error with an explicit message. `Block.validate` now passes `title` into the lifecycle
policy, and the unit suite includes a regression test that rejects
`Implement onboarding flow`.

## Prevention

- Treat product rules from `.ai-factory/RULES.md` as domain invariants, not docs-only guidance.
- When adding or reviewing aggregate validation, compare field-level checks against the
  explicit business rules list to catch missing semantic constraints.
- Keep a regression test for activity-style titles so future refactors do not weaken
  the invariant.
